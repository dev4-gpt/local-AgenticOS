# V96 starred portfolio wave plan

This is the planning inventory for the starred repositories returned from
[`github.com/dev4-gpt?tab=stars`](https://github.com/dev4-gpt?tab=stars) on
2026-08-20. The historical snapshot contained 100 repositories. The current
GitHub API reconciliation contains 101 repositories; the additional current
star is preserved in the machine-readable snapshot below.

This file is not an installer and is not the executable repository catalog.
Each row is a candidate input to a Veloce-owned trait, playbook, adapter, or
operator reference. A source becomes executable only after it has a clean URL,
an exact commit or tag, a confirmed license, declared permissions, an isolated
runtime boundary where needed, focused tests, and the relevant local/cloud
evidence. Until then it remains a reference or gated candidate.

The exact machine-readable reconciliation for this snapshot is
`src/lib/v96StarredPortfolio.ts`. It records the current commit SHA, GitHub
license metadata, extracted behavior category, permissions, placement,
activation class, evidence gate, rollback rule, and security notes for all 101
current sources. This Markdown table remains the human-readable disposition
index, while the earlier 100-entry table is retained as historical context.

## Wave policy

| Wave | Purpose | Allowed outcome |
|---|---|---|
| 3 | Bounded loops, routing, resumability, cost and anti-spin | Native Veloce traits and loop contracts; no upstream runtime import |
| 4 | Client-ready roles, playbooks, quality and domain workflows | Read-only or automatically selected native playbooks |
| 5 | Harness audit, memory, tools, operator control and cost observability | Audit rules, contracts, and operator references |
| Gated | GPU, visual media, security execution, external action, heavy runtimes | Contract/admission checks only until a separate evidence bundle passes |
| Reference | Education, curation, unresolved or license-constrained sources | Documentation only; never selected for execution |

## Activation rules

- A portfolio row is not a catalog row. The executable catalog requires a real
  pin, confirmed license, provenance, permissions, rollback rule, and evidence.
- A native-enabled row means Veloce-owned code is executing; it never means the
  upstream repository was copied into the Next.js image.
- Contract-active means the Veloce boundary exists but the upstream runtime is
  not executed. Reference-only means guidance only. Gated means admission and
  contract checks exist but execution is disabled.
- No user-facing “install skill,” “add tool,” or provider selector is added.
  Intent routing may automatically choose only enabled, native/client-ready
  playbooks under the tenant policy.
- Sources with no LICENSE, `NOASSERTION`, GPL/AGPL, or custom/unclear terms need
  the appropriate license disposition before any reuse. Hosted consumption is
  not the same as vendoring.

## Verification checklist for each adoption

1. Resolve the clean repository URL and exact commit/tag.
2. Confirm license and record attribution/provenance.
3. Extract the behavior into a Veloce trait, playbook, or adapter contract.
4. Declare permissions, runtime class, local/cloud placement, and rollback.
5. Add focused tests, redaction checks, tenant isolation, budget, idempotency,
   and failure-disposition evidence.
6. Run local and owner-cloud smoke where the capability is enabled.
7. Promote the row only after the evidence bundle is durable and reviewable.

Wave 4A has begun locally with eight native specialist playbooks. The next
concrete gate is still the Wave 3/Wave 4 shared cloud image smoke. After that,
expand the specialist-role and quality subset (`wshobson/agents`,
`agent-skills`, `agents.md`, `social-media-skills`, and the quality references)
in measured slices rather than activating all 60–80 industry candidates at
once. Wave 5 adds the cost/observability row to the harness audit before broad
adoption. Wave 4C now compiles 14 industry families into 28 bounded native
outcomes. Wave 5A now has a local six-row evidence reducer, and Wave 5B measures
standing instruction cost at the provider boundary; both deliberately report
`review` for cloud until a real cloud snapshot exists.
