`infrastructure/engineering-controls/agent-efficiency.manifest.json` applies

### Personal video Content OS

**Status: staged as a manual, approval-gated next step; no media or social
provider is connected.**

The [AI Video Generation Strategy Blueprint](https://share.gemini.google/VGI8JH19QeFI)
is represented by the secret-free
`infrastructure/content-os/personal-video-pilot.manifest.json` and the typed
pipeline contract in `src/lib/contentOsVideoPilot.ts`. It composes the existing
Hermes `video` factory sequence—brief, research, plan, draft, assets, quality,
approval, publish—into a bounded first phase of three to five 30–60 second
vertical portfolio videos. Hooks, architecture, real demo, captions, CTA,
source verification, disclosure, and owner review are required before a
delivery record may be made.

Gemini Flow/Veo, HeyGen, ElevenLabs, analytics import, scheduling, and native
platform posting are all explicitly disabled. The current pipeline only adds
the relevant guardrails when the Content OS is named; it cannot call a media
provider, accept credentials, schedule, or publish. Activation remains gated
on owner likeness/voice consent, provider terms and spend controls, human
review of disclosure and technical accuracy, retention/deletion controls, and
a separate native-publishing acceptance record. `npm run
verify:content-os-video-pilot` enforces that disabled state.

### Governed pipeline and backend registry

`infrastructure/integration-control-plane.manifest.json` is the single
secret-free registry for Ponytail, Headroom, OpenReply, VoxCPM, and Scout. It
is returned by the integration backend, rendered in the operator integrations
surface, and injected into a pipeline plan only when the candidate is named.
The planner receives the data boundary, activation evidence, and rollback
instruction, then is explicitly forbidden from activating or deploying a
candidate. This makes the useful integration state visible across pipeline,
infrastructure, stack, and backend without introducing an upstream runtime or
credential path. `npm run verify:integration-governance` passes.

### Live public-surface probe

The deployed release was checked without submitting an onboarding form or
triggering any provider, payment, or credential action. A real Chrome session
loaded `https://app.veloceos.cloud/` and confirmed the expected document title,
the Renaissance hero, the search control, and all 12 operating-pillar links.

hydrated browser read of `/start` returned HTTP 200 and contained the expected
onboarding copy, including the managed-provider wallet field.

This is deliberately recorded as a bounded public-surface probe, **not** as the
formal customer-journey acceptance result. The latter also requires the owner
to run and retain the complete release test record.

The latest production artifact also repairs the onboarding select accessibility
contract. Its source change gives the provider usage, credential model,
approval rule, media requirement, support level, and managed-service selects
explicit accessible names. The Vercel-rendered `/start` response contains those
labels and the no-credentials intake notice. Product TypeScript and the
production build both passed before that artifact was published. The local
Playwright MCP reporter subsequently failed to initialise before collecting a
test: the officially current `@playwright/test` and `playwright` 1.62.1 packages
both resolve, but the bundled MCP `testContext` extends a `ListReporter` export
that the packaged runner does not expose. This is an upstream packaging defect,
not an application-test result. The direct rendered-markup check is therefore
recorded as such, rather than misrepresenting it as a completed suite run.
