**Local setup-link update, 2026-09-29:** The setup API now sends Supabase sign-in to the public `/auth/callback` route, and a new v46 RPC atomically consumes the setup token, binds the owner membership, and records the auth user. Local database tests cover replay, expiry, revocation, suspension, existing-user mismatch, privilege boundaries, and rollback. This does not satisfy J08 until the migration, redirect allowlist, signed-in browser route, and recovery path are verified on a disposable hosted tenant.

The local callback tests additionally verify that the public handoff strips URL-fragment credentials, resolves exactly one active runtime for the authenticated user, and rejects ambiguous or non-Cloud-Run destinations before the tenant runtime accepts a rotated session. These are simulated API/browser-contract checks, not a hosted J08 receipt.

Checkout retries now send a stable Stripe idempotency key for the same approved quote, reuse a recorded open session, block changed quotes and completed billing states, and require the session ID to be saved before returning success. These are local behavioral tests only. Stripe may prune idempotency keys after 24 hours; an expired/changed session requires deliberate reconciliation rather than silently creating another session. Test-mode staging evidence and webhook ordering remain required.

Public-launch paid webhooks now reject a Checkout session ID that conflicts with the request's recorded session ID, and conditionally write the matching ID so a concurrent change cannot be overwritten. A missing local session ID can still be filled by the signed paid event after a failed Checkout persistence attempt. This is covered by local regression tests, not a Stripe Test-mode receipt; J04 remains incomplete until signed duplicate/reordered events are exercised against disposable staging data.

**Local webhook update, 2026-09-29:** A local signed-payload regression now verifies signature rejection after tampering, duplicate delivery without repeat writes, conflict rejection when the same event ID has different bytes, and a late paid checkout event that cannot move an activated onboarding account back to manifest review. **Local manifest-integrity update, 2026-09-29:** Prepare runs now retain the full approved-manifest SHA-256 through the provisioner callback.
