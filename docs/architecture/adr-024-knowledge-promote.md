# ADR-024: Knowledge adapter: the promote step

Status: built locally on `feat/knowledge-adapter` (2026-10-28). Closes the "nothing in the host calls `isPromotable`" gap in tracker Phase 3 and adds the round-trip test. Builds on ADR-005, ADR-013 (how an adapter's proposals reach the host) and ADR-020 to ADR-023. Nothing here touches the hosted client edition, and nothing is pushed (X-18).

## Decisions

1. **The Knowledge side only proposes.** `scripts/knowledge-unify/promote.mjs` turns pages into `memory.propose` events in an append-only outbox (`events.json`, mode 0600, outside every store). The host's puller (ADR-013) reads them, recomputes the hash, runs its own scan and queues a quarantined promotion for two-person review. Nothing here writes to a vault or calls the host, so the adapter holds no host credential.
2. **What becomes an event.** A page must be `shared-ok` (`isPromotable`; legacy notes without a `type` and invalid pages never are), fit the host's length limit (2,000 by default; see the addendum on raising it), have an http(s) source address (`canonical_url`, else the first http(s) entry in `sources`), pass the host scanner as `clean` (a `flagged` page is skipped, not queued, because the owner should look at it first), and not already be in the outbox at this content. Every skip is listed with its reason; the report never holds page text.
3. **Same page, same content, one event.** The citation id is a hash of the store label, the path and the page's own `sha256`. A second run proposes nothing new; an edited page is proposed again. Applying one plan twice cannot double an event.
4. **The outbox fails closed.** Numbers must continue from 1 with no gaps, and a malformed file stops the run. It is written through a temporary file and renamed. The adapter id comes from the command line or configuration, never from a page.
5. **Deletion round trip.** A page promoted to the host keeps its own copy there. When the source is deleted and the cascade removes the page, `promote.mjs orphans` lists the proposals whose page is gone or changed so the host copy can be withdrawn. Pages that cite both a web address and a local file are only listed for review by the default cascade (the web address remains a source); the owner can choose `partial: delete` for them.

## Not covered

- The host's puller handles `memory.propose` only; it counts any other kind as unknown. A `memory.tombstone` event for withdrawn proposals is the contract (ADR-005) but is not pulled yet, so orphans are reported, not withdrawn automatically.
- Serving the outbox as `GET /h1/events` with the host's token check needs an adapter service; none exists for Knowledge yet. The outbox format is the feed body, so a small service can serve it unchanged.
- Pages whose only sources are local files have no public address and are skipped (`no-public-source`) unless `--stand-in` is given (built 2026-10-29, off by default): they then get `https://<store>.knowledge.invalid/<page>`. `.invalid` can never resolve, so nothing can fetch it, and a real address is never replaced. The host's reviewer sees it is a location, not a web page.
- Real-vault runs so far are dry runs with counts only (2026-10-28, with the owner's go-ahead): promote found 0 of 1,434 pages promotable. Nothing has been written to any vault.

## Addendum: repair plan for invalid pages (2026-10-28)

`scripts/knowledge-unify/repair.mjs plan` is read-only. For each typed page that fails the check it proposes only fixes fully determined by the page itself: the page's own `sha256`, a `canonical_url` taken from the first web address in `sources` (source pages only), and a single `sources` string wrapped as a list. A page is called repairable only if the patched page then passes the WHOLE check; otherwise it is left unpatched and its remaining rule names are counted. It never invents provenance, a licence, a date, a type or a title. On the three real vaults (dry run, counts only): 84 invalid pages, 41 repairable (all in llm-wiki), 43 need a person (no sources, dates, licence or origin; 35 also have an unknown type, 25 no title). `repair.mjs apply` (dry run by default; `--apply` writes) adds only the page's own `sha256` and, for source pages, the `canonical_url`, through the same backup-and-roll-back writer as the duplicate markers; it refuses folders claimed by another device, drops a page that changed since planning, and re-checks the whole page. It was applied to the 41 on 2026-10-28 with the owner's go-ahead (originals under `~/Documents/Codex/knowledge-backups/repair-2026-10-28`); the schema check then reports 41 shareable, 1,350 legacy, 43 invalid. Three of its checks (safe path, post-edit re-check, body unchanged) are defensive layers that earlier steps already guarantee, so deliberate breakage of them is not caught by a test.

## Addendum: raising the length limit (2026-10-28)

All 41 shareable pages were over 2,000 characters (median about 5,200, longest about 16,400), so nothing could be proposed. The limit is now a per-adapter host setting, `ADAPTER_MAX_PROPOSAL_CHARS` (whole number 1 to 30,000, default 2,000), read by `run-adapter-events-puller.mjs` and passed to the puller, which also shrinks its page size so a feed page stays under the 1 MiB response cap. `promote.mjs --max-chars N` must match it. 30,000 is the most the database accepts and the most the scanner covers, so a raised limit loses no scanning. `--excerpt` (a plain cut with a visible note, no rewriting) is an optional fallback for pages still over the limit. Real vault dry run (llm-wiki only, counts only, `--max-chars 20000`): 26 of the 41 would be proposed whole, 15 are skipped as `scan-flagged` for the owner to look at, nothing written. Nothing has been applied to an outbox yet.
