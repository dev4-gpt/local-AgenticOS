## Step 5 — Implement the tracked v3.3 lifecycle

### 5A — Create the migration in Git

Create this new file:

    /home/aryamandev777/veloce-agenticos-source/product-experience/supabase-v33-managed-credit-lifecycle.sql

The migration must extend the existing v3.1/v3.2 tables and add:

- purchase-plan allocation records so partial refunds cannot be applied twice;
- reservation records and status transitions;
- quoted, reserved, actual, settled, refunded, and expired amounts;
- provider request IDs and pricing snapshot IDs;
- expiration and settlement timestamps;
- idempotency keys and duplicate handling;
- reconciliation status and metadata;
- failure reasons and audit metadata;
- server-side reserve, settle, refund, and stale-expiration functions;
- RLS and grants that prevent browser writes to the control plane.

It must preserve the distinction between wallet funding and provider readiness.
It must not enable OpenRouter.

### 5C — Update the Stripe webhook

Modify:

    /home/aryamandev777/veloce-agenticos-source/product-experience/src/app/api/billing/webhook/route.ts

The existing route handles successful managed-credit checkout. Add idempotent,
ledger-backed handling for:

    checkout.session.completed
    checkout.session.expired
    payment_intent.payment_failed
    charge.refunded
    charge.dispute.created

Every event path must read the raw body, verify Stripe-Signature before parsing
or mutating state, check stripe_webhook_events by event ID, preserve tenant and
allocation metadata, preserve Stripe mode and payment identifiers, write one
ledger transition, return HTTP 200 for safe replay, fail closed on missing
metadata, and never enable or claim OpenRouter provider credit.

Stripe’s requirements are documented in the
[webhook documentation](https://docs.stripe.com/webhooks) and
[signature guidance](https://docs.stripe.com/webhooks/signature).
