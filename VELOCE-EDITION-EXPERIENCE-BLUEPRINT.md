# Veloce AgenticOS Edition Experience

## Intent

Veloce uses a scroll-led product story to explain a managed operating system. It is an original Veloce experience, informed by high-level public interaction principles only. It must not reproduce another company's assets, copy, code, screenshots, or distinctive page layouts.

## Product Boundary

- **Public site:** safe sample data, service story, pricing anchors, and qualification CTA.
- **Private Control Room:** live agents, local files, vaults, provider status, and execution tools.
- **Client workspace, later:** authenticated, read-only deliverables and decisions before any execution access is considered.

## Edition Grammar

Every chapter follows the same useful sequence:

1. State one operational tension.
2. Reveal a single original system scene.
3. Show one concrete proof artifact.
4. Surface the 3-6 existing tools that make the outcome possible.
5. Provide a clear next action and return path to the system index.

The six Veloce chapters are:

| Chapter | Story | Private destinations |
|---|---|---|
| Command | Fragmented work becomes a coordinated operating view. | Mission Control, Claude, Codex, Hermes, OpenClaw, Antigravity |
| Context | Approved reasoning becomes reusable memory. | Memory, Notebook, Obsidian, Graphify |
| Orchestrate | Work travels through accountable lanes. | Paperclip, Pipeline, Agent Kanban, Loop, Ruflo |
| Create | Strategy becomes an original, production-ready asset direction. | Flow Lab, Web Studio, Open Design, Video, Music, Thumbnails |
| Govern | Automation operates within explicit human and cost boundaries. | Integrations, model routing, approvals, health |
| Deliver | Approved work becomes visible outcomes and reusable playbooks. | Reporting, launch assets, content and delivery workflows |

## Motion Rules

- Motion explains cause and effect; it does not decorate empty space.
- A scene remains pinned for one viewport while content progresses through it.
- UI transitions use Motion/Framer Motion. Three.js owns depth scenes. GSAP is reserved for complex scrubbed sequences after a focused project-level review.
- Every scene has a non-WebGL, reduced-motion, keyboard-readable fallback.
- No critical copy, state, or CTA may live exclusively inside canvas.

## Public Reference Study

The July 2026 authorized screen walkthrough of Shopify Editions was studied as a
reference for **pacing only**. The useful interaction grammar is:

1. Begin with a high-contrast editorial hero that establishes the edition's point of view.
2. Give each topic a distinct visual world before introducing product detail.
3. Alternate large visual proof moments with calmer, dense interface evidence.
4. Let a chapter resolve before the next one changes the mood, subject, and anchor copy.
5. Reorient the visitor with a clear category label and a route back to the broader index.

Veloce translates that grammar into its six operational lenses. It does not reuse
Shopify imagery, animation frames, words, typography, component layouts, or page
structure. Veloce scenes remain procedural or owned, and its proof artifacts are
workflow maps, approval records, private-memory diagrams, budget policies, and
delivery timelines.

## Original Asset Directions

### 1. Signal Lattice

Dots representing briefs, decisions, research, and tasks drift separately, then establish a connected operating lattice. This introduces **Command** and **Orchestrate**.

### 2. Vault Topology

Source fragments enter a private vault, become connected memory nodes, and emerge as a grounded brief. This introduces **Context**.

### 3. Approval Engine

Parallel work moves to a visible approval gate before becoming a client-ready outcome. This introduces **Govern** and **Deliver**.

All visuals are built from original procedural geometry, Veloce UI captures, or licensed/generated media. Never import a third-party brand's imagery or frame sequence.

## Asset Workflow Policy

Flow Lab may produce four approved implementation recipes:

- **Interactive node scene:** procedural Three.js nodes and lines with a DOM fallback.
- **SVG path sequence:** original paths only, drawn with CSS/GSAP-style stroke animation.
- **Owned frame sequence:** only frames created by Veloce or supplied by an authorized client; compress and preload selectively.
- **Short motion study:** licensed or owned video used as a non-essential visual layer.

Frame sequences are not the default. They can impose large download and memory costs, so a short video, procedural scene, or SVG should be selected first when it communicates the same idea.

## Client Skill Boundary

Clients can request assets through approved Veloce capabilities. They cannot install arbitrary skills, MCP servers, HTML, scripts, or external connectors into a shared workspace. Each enabled capability needs an owner, client scope, cost policy, audit trail, and human approval boundary.

## Acceptance

- Existing private routes remain direct and functional.
- Desktop, mobile, reduced-motion, and non-WebGL states preserve the same narrative.
- Public artifacts contain no local route, private path, key, vault detail, provider control, or execution capability.
- Every Flow Lab output records a permission basis and originality guardrails.
